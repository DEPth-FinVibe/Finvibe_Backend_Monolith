# KIS 실시간 구독 용량 및 실패 처리 개선 Decisions

## 결정 상태

- 사용자가 2026-08-21 D1~D5를 각각 A로 명시적으로 선택했다.
- 각 결정은 순서대로 기록, 구현, 검증한다.

## D1. 실시간 구독 tier 우선순위

### 검토한 선택지

- A: 예약 종목 → 활성 watcher → 보유 종목 순으로 배정하고 보유 종목은 남은 슬롯만 사용한다.
- B: 예약 종목 → 보유 종목 → 활성 watcher 순으로 배정한다.
- C: 예약 종목과 활성 watcher만 구독하고 보유 종목은 제외한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- 현재가 이벤트로 조건을 판정하는 예약 주문을 가장 먼저 보호한다.
- 활성 watcher 경로가 도입되거나 복구되면 전체 보유 목록보다 실제 활성 수요를 우선한다.
- 예약과 watcher가 사용하지 않은 슬롯은 보유 종목에 배정해 기존 동작과의 단절을 줄인다.

### 감수한 트레이드오프

- 현재 운영 코드에는 watcher 생성 호출 경로가 없어 당장은 예약 다음에 일부 보유 종목이 선택된다.
- 전체 보유 종목 중 용량 밖 종목은 WebSocket 실시간 이벤트를 받지 못한다.

## D2. 같은 tier가 남은 용량을 초과할 때의 선정 정책

### 검토한 선택지

- A: 현재 실제 구독 중인 종목을 먼저 유지하고 남은 자리는 `stockId` 오름차순으로 채운다.
- B: 동기화 주기마다 초과 종목을 순환한다.
- C: Redis에 최근 활동 시각을 저장하고 가장 최근 종목을 우선한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- Redis와 repository가 반환하는 collection 순서에 관계없이 결과를 결정적으로 유지한다.
- 실제 구독 중인 종목을 먼저 유지해 불필요한 KIS 구독·해제와 가격 공백을 줄인다.
- 새 활동 projection이나 호출 경로를 추가하지 않고 현재 장애 범위 안에서 구현할 수 있다.

### 감수한 트레이드오프

- 같은 tier의 후순위 종목은 장중에 계속 선택되지 않을 수 있다.
- 프로세스 재시작으로 로컬 구독 상태가 초기화되면 `stockId`가 작은 종목부터 다시 선택된다.

## D3. `subscribe()`의 성공·실패 계약

### 검토한 선택지

- A: 신규 성공, 기존 구독, 세션 부재, 용량 소진과 전송 실패를 구분하는 명시적 결과 타입을 반환한다.
- B: 성공 여부만 boolean으로 반환한다.
- C: 예상된 세션 부재와 용량 초과도 예외로 전달한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- 스케줄러가 실제 구독 성공 여부와 실패 원인을 기준으로 로컬 순서 및 분산 소유권을 처리할 수 있다.
- 정상적인 용량 backpressure와 예기치 않은 전송 실패를 로그와 메트릭에서 구분한다.
- 세션 부재를 정상 반환으로 숨겨 실패를 성공으로 기록하던 현재 결함을 제거한다.

### 감수한 트레이드오프

- `MarketDataStreamPort`, KIS adapter, mock adapter와 관련 테스트의 계약을 함께 변경해야 한다.
- 새 결과 상태를 추가할 때 scheduler의 상태별 처리도 함께 갱신해야 한다.

## D4. 연결된 세션 용량이 0일 때의 동기화 동작

### 검토한 선택지

- A: 해당 주기를 즉시 종료하고 다음 5초 주기에 세션 동기화부터 다시 시도한다.
- B: scheduler thread에서 제한 시간 동안 연결 완료를 기다린다.
- C: 후보를 계속 처리하고 adapter가 종목별로 세션 부재를 거절하게 한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- 세션이 준비되지 않은 동안 7,384개 후보 조회, 종목별 분산 락과 반복 오류를 만들지 않는다.
- 비동기 WebSocket 연결을 scheduler의 동기 대기로 바꾸지 않는다.
- 기존 5초 동기화 주기로 준비 상태를 다시 확인해 자동 복구할 수 있다.

### 감수한 트레이드오프

- 세션이 주기 직후 연결되면 실제 구독 시작까지 최대 약 5초를 추가로 기다릴 수 있다.
- 세션 준비 중에는 해당 노드의 실시간 현재가 이벤트가 발생하지 않는다.
