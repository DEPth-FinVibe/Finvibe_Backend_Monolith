# 장외 시세와 휴장일 판정 신뢰성 개선

## 연결 Issue

- Issue: [#7 fix: 장외 시세와 휴장일 판정 신뢰성 개선](https://github.com/DEPth-FinVibe/Finvibe_Backend_Monolith/issues/7)

## 배경과 실제 증상

운영 환경의 시세 공급자가 KIS로 전환되었지만 장외 시간 또는 서버·시세 저장소의 콜드 상태에서는 최근 거래일 종가가 사용자 요청 중 외부 KIS API 호출로 보충된다.

다수 종목을 조회할 때 KIS 멀티종목 호출은 30종목 단위로 분할된다. 현재 구현은 특정 배치가 실패해도 다음 배치를 계속 처리하고, 최종 종가 응답에서는 가격을 확보하지 못한 종목을 제외한다. 따라서 호출자는 정상적인 빈 데이터와 외부 시세 일부 실패를 구분하기 어렵다.

시장 상태는 `MarketHours`가 주말과 09:00~15:30 시간만으로 판정한다. 종가 조회는 `HolidayCalendarService`로 최근 거래일을 계산하므로, 평일 거래소 휴장일에는 상태 판정과 종가 기준일 계산이 서로 다른 규칙을 사용할 수 있다.

## 현재 구현과 확인된 사실

- `MarketHours`에는 한국 공휴일 및 거래소 휴장일 반영 TODO가 남아 있다.
- `MarketStatusService`는 `MarketHours.getCurrentStatus()` 결과를 그대로 반환한다.
- 장외 `getClosingPrices`는 DB에 최근 거래일 종가가 없으면 요청 스레드에서 `RealMarketClient.bulkFetchCurrentPrices`를 호출한다.
- `RealMarketClientImpl.bulkFetchCurrentPrices`는 실패한 30종목 배치를 로그로 남긴 뒤 결과에서 누락한다.
- 종가 응답은 요청한 ID 중 데이터를 확보한 종목만 반환한다.
- 별도 Batch 애플리케이션은 장중 가격 업데이트를 수행하지만 장 마감 전체 종가를 사전 적재하는 전용 작업은 없다.
- 종가 정리 작업은 장이 열릴 때 저장된 종가를 전체 삭제한다.

## 해결해야 하는 문제

1. 시장 상태와 최근 거래일 계산이 동일한 휴장일 규칙을 사용해야 한다.
2. 장외 첫 요청이 대량 KIS 호출과 저장 비용을 직접 부담하지 않아야 한다.
3. 요청 종목 중 일부 시세를 확보하지 못한 상태를 정상 전체 응답처럼 처리하지 않아야 한다.
4. 소비자가 가격 종류와 기준 거래일·시각을 식별할 수 있어야 한다.
5. 배치 및 외부 시세 실패를 운영 지표로 탐지할 수 있어야 한다.

## 변경 범위

- 시장 상태 판정을 휴장일 달력과 통합
- 최근 거래일 종가 조회 및 저장 정책 정리
- 장 마감 종가 사전 적재 또는 워밍업 배치 경로 추가
- KIS 멀티종목 부분 실패 계약 개선
- 기존 `/market/stocks/closing-prices` 소비자 호환성 검토
- 시장 상태·종가 응답의 데이터 기준 시각 제공 방안 검토
- 관련 단위 테스트, 통합 테스트와 Micrometer 지표 추가
- Monolith와 Batch 저장소 간 공유 코드 반영 방식 문서화

## 제외 범위

- Kubernetes replica, probe, graceful shutdown 등 무중단 배포 개선
- 프론트엔드 UI, 반응형 레이아웃과 목업 폴백 변경
- 뉴스 크롤링·분석 배치 개선
- 스쿼드 조회 집계 API
- 실주문, 체결과 수익 계산 로직
- 장중 WebSocket 프로토콜 변경

## 예상 위험과 제약

- 시장 상태 응답 enum을 확장하면 기존 프론트 타입과 분기 로직이 깨질 수 있다.
- 종가 응답 구조를 감싸는 형태로 변경하면 기존 API 소비자와 호환되지 않는다.
- 전체 종목 종가 워밍업은 KIS 호출 제한과 Batch 실행 시간을 증가시킨다.
- 종가 데이터를 거래일별로 보존하면 DB 사용량과 정리 정책이 필요하다.
- Monolith와 Batch에 동일한 market 코드가 복제되어 있어 한쪽만 변경하면 운영 동작과 API 동작이 달라질 수 있다.
- 현재 두 저장소의 기본 worktree에는 사용자 변경이 있으므로 별도 worktree에서만 작업해야 한다.

## 검증 가능한 완료 기준

- 평일 거래소 휴장일에 시장 상태가 `OPEN`으로 반환되지 않는다.
- 장외 종가 조회가 최근 거래일과 기준 시각을 일관되게 사용한다.
- 요청한 종목의 일부 시세 확보 실패가 식별 가능한 계약 또는 오류로 노출된다.
- 사용자 요청 전에 종가를 적재할 수 있는 배치 실행 경로가 존재한다.
- 기존 API 호환성 또는 명시적인 마이그레이션 경로가 결정 문서에 기록된다.
- 관련 Monolith·Batch 테스트가 통과한다.
