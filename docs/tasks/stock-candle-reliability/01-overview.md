# 종목 캔들 조회 신뢰성 개선 Overview

## 연결 Issue

- Issue: [#9 fix: 종목 캔들 조회 신뢰성 개선](https://github.com/DEPth-FinVibe/Finvibe_Backend_Monolith/issues/9)

## 작업 배경과 실제 증상

- 실서비스 `https://finvibe.space/simulation/4971`에서 분봉·일봉·주봉 차트가 비어 있고 “해당 기간의 차트 데이터가 없습니다.”가 표시된다.
- 2026-08-21 KST 재현 시 `MINUTE`, `DAY`, `WEEK` 캔들 API는 모두 HTTP 500을 반환했다.
- 같은 시점에 시장 상태, 종목 단건, 뉴스 등 백엔드 업무 API도 함께 500을 반환했으므로 배포 또는 서버 장애와 캔들 고유 문제를 분리해 재검증해야 한다.
- 사용자 요구에 따라 내부 장애가 일반 500으로 노출되는 동작은 허용하지 않는다.

## 현재 구현과 확인된 사실

- `MarketQueryService`는 요청 구간에서 산술적으로 모든 캔들 시각을 생성하고 DB에 없는 시각을 외부 조회 대상으로 삼는다.
- 외부 응답에 포함되지 않은 시각은 `PriceCandle.isMissing=true`로 저장되며 이후 조회에서는 이미 확인된 시각으로 취급된다.
- 분봉의 예상 시각 계산은 장 운영 시간, 주말과 휴장일을 걸러내지 않아 비거래 시간도 결측 행으로 저장할 수 있다.
- 분봉 KIS 호출은 재시도 소진 뒤 `null`을 반환할 수 있고, 호출 전체가 비었는지와 실제 캔들이 없는지를 호출자가 구분할 수 없다.
- 일·주·월·년봉 KIS 호출도 빈 응답을 정상적인 데이터 없음과 제공자 실패로 구분하지 않는다.
- 결측 행에는 만료 또는 재검증 시점이 없으므로 일시적인 제공자 실패가 영구적인 빈 차트로 고착될 수 있다.
- 기존 `GET /market/stocks/{stockId}/candles`는 배열 응답이며 프론트가 직접 사용한다.

## 해결해야 하는 문제

1. KIS 실패 또는 비정상 빈 응답을 영구 결측으로 저장하지 않는다.
2. 유효한 캐시가 있으면 외부 장애 중에도 캐시를 반환한다.
3. 유효한 캐시가 없고 외부 조회도 실패하면 일반 500이 아닌 명시적인 503으로 응답한다.
4. 분봉의 결측 후보를 실제 거래일과 장 운영 시간으로 제한한다.
5. 기존에 저장된 잘못된 결측 행이 정상 데이터 재조회를 막지 않도록 복구한다.
6. 분봉·일봉·주봉의 정상, 캐시, 외부 장애 경로를 검증한다.
7. 실시간 체결 이벤트를 분봉으로 집계·저장하고, 재시작·미구독·수신 누락 구간은 KIS REST 조회로 복구한다.

## 변경 범위

- Monolith `market` 모듈의 종목 캔들 조회 흐름
- KIS 캔들 조회 결과의 성공·실패 표현
- 결측 후보 계산과 저장 정책
- 기존 `price_candle.is_missing=true` 데이터의 복구 경로
- 캔들 조회 관련 예외 코드와 HTTP 상태 매핑
- WebSocket 실시간 체결의 1분 OHLCV 집계·저장과 KIS REST 복구 경로
- 장애·캐시 fallback·조회 결과 관측을 위한 로그와 메트릭
- 관련 단위 및 통합 테스트와 실서비스 API 재검증

## 제외 범위

- 프론트 UI 및 기존 캔들 배열 응답 형식 변경
- Batch와 뉴스 수집 변경
- 무중단 배포
- 월봉·년봉의 별도 기능 확장
- 차트 라이브러리 및 프론트 WebSocket 실시간 갱신 로직 변경

## 예상 위험과 제약

- 영구 결측 캐시를 축소하면 같은 미확인 구간에 대한 KIS 호출량이 증가할 수 있다.
- 기존 결측 행을 한 번에 정리하면 DB 부하와 락 경합이 발생할 수 있어 적용 범위를 별도로 결정해야 한다.
- 과거 mock 오염 제거를 위해 종목 캔들 전체를 삭제하면 KIS가 제공하지 않는 오래된 분봉은 복구되지 않을 수 있다.
- 종목 캔들 전체 삭제는 운영 데이터 변경이므로 백업, 대상 건수 확인, 분할 실행과 사후 검증이 선행되어야 한다.
- KIS WebSocket 이벤트의 OHLC와 누적 거래량·거래대금은 당일 기준이므로 분봉 값으로 직접 저장하면 안 된다.
- 모든 체결을 DB에 즉시 저장하면 장중 쓰기 부하와 동일 분봉 행 경합이 커지며, 분 경계에서만 저장하면 재시작 시 현재 분이 유실될 수 있다.
- 현재 진행 중인 분봉을 KIS REST 응답과 WebSocket 집계가 동시에 갱신하면 최신 체결이 과거 REST 스냅샷으로 되돌아갈 수 있다.
- 외부 장애를 503으로 구분하면 기존 500 기반 모니터링 수치와 알림 조건이 달라질 수 있다.
- 주봉은 KIS 원본 날짜와 내부 주 시작일 정규화가 다르므로 중복·누락 방지 테스트가 필요하다.
- 현재 실서비스 백엔드 업무 API 전체가 500을 반환하고 있어 서버 정상화 전에는 운영 완료 검증을 할 수 없다.

## 승인 내용

- 사용자는 2026-08-21 위 문제 정의, 변경 범위와 제외 범위를 승인했다.
- 사용자는 KIS 실패·비정상 빈 응답을 영구 결측으로 저장하지 않고, 캐시가 있으면 반환하며 캐시가 없으면 503으로 처리하는 방향에 동의했다. 이 선택은 Plan 승인 후 결정 기록에 정식 반영한다.
- 사용자는 2026-08-21 배포 이후 실데이터 분봉이 한 건도 적재되지 않은 진행형 장애를 확인하고, KIS REST 복구와 WebSocket 분봉 집계를 함께 적용하는 혼합 방식을 승인했다. 배치 작업은 추가하지 않는다.
- 사용자는 과거 mock 오염 데이터의 정확한 생성 범위를 식별할 메타데이터가 없는 제약을 감수하고, 종목 캔들 전체 삭제 후 KIS 재조회로 복구하는 방식을 승인했다. 실제 삭제는 별도 운영 확인 후 수행한다.
- 사용자는 실시간 분봉을 개별 체결가와 체결량으로 집계하고, 메시지 유실 구간은 KIS REST 조회로 보완하는 방식을 승인했다.
- 사용자는 분봉을 메모리에서 집계하고 5초 주기, 분 경계와 정상 종료 시 DB에 flush하는 방식을 승인했다.
- 사용자는 현재 진행 중인 분봉은 WebSocket 집계가 소유하고, 완료된 분봉만 KIS REST 결과로 최종 보정하는 방식을 승인했다.
- 사용자는 종목 캔들 전체 삭제를 배포 자동화나 관리자 API로 실행하지 않고, 별도 운영 SQL과 절차를 확인한 뒤 수동 분할 실행하는 방식을 승인했다.
