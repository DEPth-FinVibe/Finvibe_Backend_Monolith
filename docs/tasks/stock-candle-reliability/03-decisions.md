# 종목 캔들 조회 신뢰성 개선 Decisions

## 결정 상태

- 사용자가 2026-08-21 D1~D5를 순서대로 모두 A로 명시적으로 선택했다.

## D1. KIS 전체 실패 또는 비정상 빈 응답 정책

### 검토한 선택지

- A: 실제 캐시가 있으면 캐시를 반환하고, 없으면 명시적 503을 반환한다.
- B: 캐시 유무와 무관하게 항상 503을 반환한다.
- C: 실패를 빈 배열로 반환한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- KIS 장애를 차트 전체 장애로 확대하지 않고 이미 확보된 실제 캔들을 제공한다.
- 정상적인 데이터 없음과 외부 장애를 빈 배열로 숨기지 않는다.
- 반환 가능한 데이터가 없을 때 의도된 503으로 구분해 일반 500 노출을 방지한다.

### 감수한 트레이드오프

- fallback 캐시가 요청 범위 전체를 포함하지 않거나 최신성이 낮을 수 있다.
- 기존 배열 응답만으로 fallback 여부를 알 수 없어 로그와 메트릭이 필요하다.

## D2. KIS 일부 호출만 성공한 경우의 응답

### 검토한 선택지

- A: 성공한 실제 캔들을 저장하고 기존 캐시와 병합해 반환하며 부분 성공 메트릭을 남긴다.
- B: 새 부분 결과는 저장하되 응답에는 기존 캐시만 반환한다.
- C: 일부 실패가 하나라도 있으면 모든 결과를 버리고 503을 반환한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- 유효한 실제 데이터를 최대한 제공해 일부 KIS 호출 실패를 전체 차트 장애로 확대하지 않는다.
- 기존 배열 API 계약을 바꾸지 않고도 차트 가용성을 높일 수 있다.
- 부분 성공은 별도 메트릭과 로그로 운영자가 식별한다.

### 감수한 트레이드오프

- 클라이언트는 응답 배열만으로 요청 구간이 완전한지 알 수 없다.
- 부분 데이터 사이에 시간 간격이 생길 수 있다.

## D3. 기존 `isMissing=true` 행 처리

### 검토한 선택지

- A: 즉시 coverage에서 제외하고 물리 삭제는 운영용 분할 삭제 SQL과 절차로 제공한다.
- B: 애플리케이션 시작 시 모든 결측 행을 자동 삭제한다.
- C: 스키마에 만료 시각을 추가하고 기존 행을 점진적으로 재검증한다.

### 결정

- 선택: A
- 결정자: 사용자
- 결정일: 2026-08-21

### 선택 이유

- 배포 직후 기존 결측 행이 정상 데이터 재조회를 막지 않게 한다.
- 대량 삭제를 애플리케이션 시작 경로에서 분리해 시작 지연과 DB 락 위험을 피한다.
- 물리 삭제는 운영자가 데이터량과 부하를 확인하며 작은 단위로 수행할 수 있다.

### 감수한 트레이드오프

- 운영 정리를 수행하기 전까지 불필요한 결측 행이 DB에 남는다.
- 분할 삭제 절차를 별도로 실행하고 완료 여부를 확인해야 한다.

- 정식 선택을 받기 전에는 결정 기록과 구현을 진행하지 않는다.
