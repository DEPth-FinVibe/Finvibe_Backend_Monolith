# 분봉 조회 성능 개선 Overview

## 연결된 Issue

- Issue: #13
- URL: https://github.com/DEPth-FinVibe/Finvibe_Backend_Monolith/issues/13

## 작업 배경과 실제 증상

종목 분봉 API로 최근 3거래일을 조회하면 운영 환경에서 응답에 5초 이상 걸린다. 같은 범위를 직접 확인했을 때 약 6.9초가 걸렸으며, 데이터는 정상 반환되어 지속적인 외부 서비스 장애가 아니라 조회 경로의 구조적인 지연으로 판단했다.

프론트엔드의 기본 분봉 범위는 최근 3일이다. 현재 백엔드는 KIS provider에서 분봉을 요청하면 DB에 정상 저장된 완료 분봉도 기존 데이터로 인정하지 않고 요청 범위 전체를 외부 API에서 다시 조회한다. KIS 분봉 조회는 거래일별 2시간 간격으로 나뉘므로 3거래일 조회 한 번에 약 12회의 순차 외부 호출이 발생한다.

## 현재 구현과 확인된 사실

- `MarketQueryService.calculateMissingCandleTimes`는 KIS의 `MINUTE` 요청에서 모든 기존 캔들 시각을 누락 계산 대상에서 제외한다.
- 그 결과 완료된 과거 분봉이 DB에 있어도 전체 범위가 `RealMarketClient` 조회 범위가 된다.
- `RealMarketClientImpl.fetchIntradayCandles`는 거래일별 조회 시각을 2시간 간격으로 나눠 순차 호출한다.
- 반복적인 전체 재조회는 응답시간뿐 아니라 KIS credential의 호출 한도와 Circuit Breaker 실패 가능성도 높인다.
- 외부 조회가 실패하면 기존 분봉을 반환하는 부분 장애 fallback은 이미 구현되어 있다.

## 해결해야 하는 문제

1. 정상 저장된 완료 과거 분봉을 매 요청마다 KIS에서 다시 조회하지 않는다.
2. 실제 누락된 분봉은 기존처럼 외부 provider에서 보충한다.
3. 장중 아직 값이 바뀔 수 있는 최근 분봉만 제한적으로 갱신한다.
4. 기존 부분 장애 fallback과 API 응답 계약을 유지한다.

## 변경 범위

- 종목 분봉의 누락 및 갱신 대상 시각 계산
- 완료된 과거 분봉의 DB 캐시 재사용
- 당일 최근 분봉의 갱신 기준
- 외부 provider 호출 범위를 검증하는 단위 테스트
- 캐시 적중 시 호출량과 응답 경로 검증

## 제외 범위

- 프론트엔드 UI와 기본 조회 기간 변경
- 일봉, 주봉, 월봉, 연봉 조회 정책
- 배치 수집과 WebSocket 분봉 집계 구조 변경
- KIS 장애, retry, Circuit Breaker와 예외 체계의 전면 개편
- API 계약과 DB 스키마 변경
- 과거 mock 데이터 정리

## 예상되는 위험과 제약

- 장중 마지막 분봉을 확정 데이터로 너무 일찍 간주하면 체결이 덜 반영된 값이 캐시에 남을 수 있다.
- 거래가 없는 분은 DB에 캔들이 없을 수 있으므로 실제 누락과 무체결을 구분하지 못하면 반복 조회가 생길 수 있다.
- 조회 범위를 하나의 시작·종료 구간으로 합치는 현재 외부 client 계약 때문에 떨어진 여러 누락 구간 사이의 캐시 데이터도 재조회될 수 있다.
- 운영 응답시간은 KIS와 DB 상태에 영향을 받으므로 테스트에서는 외부 호출 횟수와 범위를 우선 검증하고, 배포 후 실제 지연을 별도로 확인해야 한다.
